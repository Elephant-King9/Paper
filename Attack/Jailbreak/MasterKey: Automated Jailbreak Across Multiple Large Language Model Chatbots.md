**MasterKey: Automated Jailbreak Across Multiple Large Language Model Chatbots**

- **背景**

- **现有问题**

- **动机**

  - 你访问网站时，加载慢快可能暴露出网站结构；LLM 回复慢快，也可能透露其处理流程。

  - 如果你输入“含敏感词”的 prompt，模型回复变慢 → 它可能在“检查敏感词”；

    如果你输入很长但无害的 prompt，它反而很快 → 说明没用复杂分析。

- **贡献**

  - 模拟“时间型 SQL 注入”反推防御策略
  - 自动化越狱提示词生成

- **解决思路**

  - 自动化生成通用越狱提示词
    - 第一步，收集整理越狱提示词数据集
    - 第二步，用第一步的数据集训练一个专门擅长编写越狱提示的LLM
    - 第三步，利用奖励机制来抢唤醒越狱能力
  - 设计洞察
    - 我们发现，即使越狱失败，返回响应的时间也会有所不同。我们推测，这种现象是因为 LLM 在拒绝请求前，仍然执行了部分生成流程。
  - 时间性SQL注入
    - 攻击者精心设计一个判断条件（如：数据库版本的第一个字符是否为‘5’），如果条件满足，系统会执行 SLEEP(5)，延迟5秒。否则系统会跳过延迟命令并立即响应。于是，响应时间就成了判断条件是否成立的“信号”。

- **具体解决方法**

  - 研究方向
    - RQ1：主流 LLM 聊天机器人服务提供商都设定了哪些使用政策？
      - 检测模型OpenAI、Bard（Google）、Bing Chat（Microsoft）和文心一言（Ernie，百度）
      - 虽然国家文化各不相同，但是这四个平台在四个方面都采取了一致禁止：违法用途、有害或辱骂性内容、侵犯隐私与权利、成人内容
    - RQ2： 现有的越狱提示词在这些商业聊天机器人上有多大效果？
      - 我们聚焦于四个知名 LLM 聊天机器人：GPT-3.5、GPT-4、Bing Chat 和 Google Bard。
      - **现有越狱提示词几乎只对 ChatGPT 有效**，在 Bard 和 Bing Chat 上基本无效，成功率 <1%；
      - **OpenAI 的模型在拦截违规内容时反馈更明确**，会指出违规原因，而其他平台则反馈模糊甚至不响应。
