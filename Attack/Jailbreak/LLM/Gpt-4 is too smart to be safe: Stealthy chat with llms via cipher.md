**Gpt-4 is too smart to be safe: Stealthy chat with llms via cipher,**

- **背景**

- **现有问题**

  - 由于人类反馈和安全对齐主要是通过自然语言进行的，那么如果使用人类无法直接理解的“加密语言”，可能就可以绕过这些安全机制。

- **动机**

  - 如果你不是用普通语言和模型交流，而是用“暗语”说话，模型就容易放松警惕，被绕过。
  - 你甚至不用真的写“暗语”，只要告诉模型“假装某种角色”，加上几个“加密示范”，它自己就会用“内部潜意识的加密方式”配合你

- **贡献**

- **解决思路**

- CipherChat

  - 设计了一个由三部分组成的系统提示词：
    - **行为指定**：告诉 LLM 它是某种加密语言专家（例如“你是凯撒密码专家”），并明确要求它用加密语言交流。
    - **密码教学**：通过上下文教学，让 LLM 学会这种加密方式。
    - **加密示例**：提供一些用加密语言写成的不安全例子，既让 LLM 更理解加密规则，也让它“习惯”生成这类内容。
      - 教完规则后，给它看几个“有害问句”的加密版本 + 加密回答，模型就会学会“我该怎么在这种场景下生成回复”
      - 一是配合教学内容加深模型对密码的理解；二是将“不对齐”元素植入模型上下文，引导其从“危险”角度来做出回答
    - 我们发现如果不加提示词，直接输入加密内容，模型往往会把它翻译回自然语言（比如英文）。因此，我们增加了一句提示：“不要充当翻译器”，以防止这种行为
    - 模型不是“预先学过凯撒密码”才懂的，而是在你当前对话里“临时教会它”

  - 编码方式

    - GBK

    - ASCII

    - UTF-8

    - Unicode

    - Atbash Cipher

    - Morse Code 摩斯密码

    - Caesar Cipher 凯撒密码

  - 在几个领域中，使用 ASCII 编码输入英文问题，GPT-4 几乎 100% 会绕过安全机制。

  - 看起来只是普通英文对话，实际上模型因为“被设定成 Cipher 专家”，开始绕过原本的安全审查机制。

- SelfCipher

  - 模型被要求“不能用正常语言交流”，得自己“想象出”一种 Cipher Code 来用。这其实是引导它生成一种看似加密、实则它自己构造的隐藏表达方式。
  - 看起来只是普通英文对话，实际上模型因为“被设定成 Cipher 专家”，开始绕过原本的安全审查机制。
