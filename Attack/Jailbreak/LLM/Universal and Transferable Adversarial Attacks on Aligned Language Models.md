**Universal and Transferable Adversarial Attacks on Aligned Language Models**

- **背景**

  - LLMs 是在大量从互联网上抓取的文本语料上训练的。这些数据中不可避免地包含了大量不良内容，当前的模型开发者会在预训练后执行“对齐”操作，即通过微调（finetuning）等技术手段来限制模型输出不当内容。对齐机制的目标是让模型行为符合社会规范与伦理标准。表面上这些对齐方法似乎确实有效：当你直接询问一个敏感问题，公开发布的聊天机器人通常会拒绝回答，显示出一定的“安全性”。
  - 对抗样本攻击如今这已是 CV 中的经典问题。类似的对抗攻击方式也被用在 LLM 上，尽管输入不再是像素，而是文本 prompt。这些攻击被称为越狱攻击（jailbreaks），即诱导对齐后的模型输出违规或敏感内容。目前最有效的越狱攻击多数依赖人工设计，如人类“精心编写”提示词，引导模型跳过安全对齐(如以“讲故事”“模拟角色”等方式绕过规则)
  - 已经有部分研究尝试使用自动搜索算法生成 adversarial prompts（如使用梯度搜索、强化学习等）。但结果表明，相比图像任务，这种自动化攻击在文本领域效果较差，难以稳定实现。原因在于图像模型输入是连续像素，梯度空间连续可微，便于计算并优化扰动。LLM 输入是离散的 token 序列，搜索空间不连续、优化困难，导致攻击难度大。
  - 在 CV 系统中，对抗攻击至今都无法根除，即使研究了多年。即使已有不少防御方法（如 Madry、Cohen、Leino 的防御工作），这些方法在实际系统中几乎没有使用，原因包括：计算开销太高、降低模型本身性能、防御能力有限
  
- **现有问题**

  - 尽管已有“越狱攻击（jailbreak）”可以绕过对齐策略，但这些方法：
    - 依赖大量人工提示设计（human ingenuity）
    - 可迁移性差，容易失效（brittle）
  - 以往工作也尝试过类似方式（例如 Carlini et al., 2023），但：
    - 往往不稳定、成功率低，即使在白盒条件下也难以稳定越狱；
    - 原因是缺乏有效的目标函数（loss）、数据处理方式、优化策略等关键设计。
  - AutoPrompt：每次只优化一个 token 位置（一个“coordinate”）。
    - 它先选定某个位置，比如 prompt 第 2 个词；
    - 然后只尝试替换这个位置的 token。
  - GCG：对所有位置都考虑候选替换，然后从中选出最优的一组。
    - 它更“全局”，不是局部优化某一个 token，而是从所有 token 中找最值得替换的。

  - 就是这个“一个位置 vs 所有位置”的策略设计差异，效果差距很显著。全面考虑 token 替换位置的策略更有效率、更可靠。

- **动机**

  - 输入保持不变，只附加后缀（suffix）来攻击模型。诱导模型从本应拒绝的请求中生成
  - 通过自动生成的对抗后缀（adversarial suffix），绕过对齐语言模型的安全防护机制，使其产生原本不允许生成的有害内容

- **贡献**

  - **提出一种可自动生成、通用、可迁移的越狱攻击方法。不改变初始问题，而是在初始问题后添加对抗prompt来实现越狱**
  - **显著提升了当前对齐语言模型攻击的效果。**
  - **揭示了对齐机制在多模态 LLM 中的脆弱性，引发了对未来对抗防御的反思。**

- **解决思路**

  - **初始肯定相应（Initial affirmative responses）**

    - 模型一旦开始用"Sure, here is…"开头，它就会“切换模式”，接下来倾向于生成完整的违规内容
    - 攻击的第一步目标是诱导模型在响应开头产生正面表态（如“当然，这是……”）。
    - 这种表态会触发模型进入“配合生成”的状态，即使最初的问题是违规的。
  - **离散 token 的梯度搜索 + 贪婪优化（Combined greedy & gradient-based discrete optimization）**
    - 由于语言模型输入是离散 token，不能直接对输入做连续扰动（如图像那样）。虽然 token 是离散的，但我们使用梯度来引导替换候选 token 的方向
    - 该方法使用梯度信息寻找潜在替换 token，然后评估多个候选 token（不是仅替换一个），选择 loss 最低的替换，实现贪婪式搜索
  - **多提示+多模型优化（Robust multi-prompt and multi-model attacks）**
    - 训练一个能在多个模型和多个 prompt 上都生效的通用攻击后缀。

- **具体解决方法**

  - **攻击的核心目标是：找到一段对抗性后缀，使得语言模型（即使被对齐）在面对本应拒绝的问题时，仍能生成肯定的、有害的回答。**

    - 一种自然但欠佳的思路是：让模型输出一个预先指定的目标字符串（比如具体的炸弹制作步骤），并用这个目标字符串的生成概率作为优化目标（最大化 log-likelihood）。

      - **限制太死（Overly Prescriptive）**
        - 这种方法假设问题只有一个“正确”的输出（ground truth）。但现实中，模型可能以多种方式回答同一个问题（特别是在语言生成中，本身就有很高的多样性）。
      - **只能针对单个问题（Non-generalizable）**
        - 你优化的只是某一个问题（如 “如何造炸弹”）对应的后缀；无法推广到其他问题（如 “如何骗税”），也无法生成一个**通用的后缀**（universal adversarial suffix）

    ### 修改目标函数

    **将优化目标定位，生成"Sure,here is how to+问题"**

  - 诱导模型生成“肯定响应”（affirmative response），即模型愿意“开始回答”这个问题，比如以 “Sure, here is…” 开头。

  - 这个目标比生成具体句子更合理，因为它是通用的，适用于各种问题，一旦模型“肯定”用户请求，它很可能会继续生成整个有害内容。不追求唯一答案，而追求行为模式（肯定回应）；优化的不是输出的具体内容，而是模型是否愿意回答这个问题；这使得攻击具有更强的迁移性和普适性。

    - 只要求模型生成一句正面开头
      - 对于"how to build a bomb"，只要生成"Sure,here is how to build a bomb"就算成功

  - **🔍 核心问题：仅诱导一个“Sure”足够吗？**

    作者指出：

    - 以往的人工越狱方式（manual jailbreak），如加一句提示“请回答‘Sure’”，成功率并不高，一旦模型对抗能力稍微增强，这种方式就容易被拦截。

    - 在多模态模型中（比如图文输入模型），仅仅优化第一个 token（比如“Sure”），有时就足以发动攻击；

      - 但那是因为视觉输入带来了更大的“攻击面”，攻击者有更多空间诱导模型。
      - 然而在纯文本模型中，攻击空间小，仅一个 token 很可能不足以维持攻击行为。

    - 仅使用Sure,模型可能会生成，Sure,but I cannot help you 或者 Sure, here is a joke
    - 更有效的方式是让模型重复问题
      - 对于"how to build a bomb"，只要生成"Sure,here is how to build a bomb"就算成功

    ### 修改优化策略

    **使用预先构建好的词典，从词典中选词优化**

  - 表示已有方法尝试解决这个问题，例如：

    - AutoPrompt [Shin et al., 2020]：用梯度找 token 替换
    - PEZ、GBDA：用 Gumbel-Softmax 或梯度下降等技巧
    - 随机采样 + top-k 筛选

  - 但是这些方法在攻击 alignment 后的语言模型时效果并不好，原因是

    1. 模型经过 RLHF / instruction tuning 后有“拒绝”机制，对抗攻击难度更大；
    2. 离散搜索空间非常大，梯度信息容易不稳定或无效；
    3. 大部分方法无法生成在多个 prompt / 多模型上通用的攻击后缀（即不具备转移性和普适性）。

  - **为什么难？** 因为你要在离散词表中找到一串“特殊词”，让模型放弃 alignment 生成违规内容。

  - **现有方法不够强？** 对于 alignment 后的模型（如 ChatGPT、Vicuna），单靠 AutoPrompt、PEZ 等优化器往往不稳定、不具备迁移能力。

- **实验**

  - **100 个有害行为测试任务中**，该方法成功诱导模型生成：

    - **99 个有害行为（99% success rate）**
    - **88 个输出中**，**完全匹配（exact match）目标字符串**，即生成了“精确”的非法内容。
